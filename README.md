# IFRS – Integrated Flood Resilience System (web app)

Group 4 · The Department of Dry Affairs · *Channel the rain and protect the terrain!*

A mobile-first web app for IFRS: rooftop rainwater tanks with smart slow-release valves, storm-drain monitoring, leak detection, citizen reporting, cleanups, rewards and a concept water-rebate programme. It's built for a demonstration at the Tatil Building prototype station in Port of Spain.

> **Demo platform.** All people, properties and readings are fictional or simulated. A persistent **DEMO DATA** banner is shown throughout. Nothing is sent to any authority. No official rebate scheme is implied.

**Live site:** https://isaacalberto.github.io/ifrs/

---

## Quick start

```bash
npm install
npm run dev        # http://localhost:5173/ifrs/
npm test           # unit tests (vitest)
npm run build      # production build in dist/
npm run deploy     # build + publish dist/ to the gh-pages branch
```

Requires Node 20+.

### What is simulated or still needs work

- **Backend / database / authentication.** This is a static demo. Roles are switched with the persona menu, and permission checks run in the browser. A production deployment needs a server (e.g. Supabase/PostgreSQL with row-level security) that enforces the same rules (`src/domain/rbac.ts`) server-side.
- **Sensors.** Readings are generated by `src/sim/engine.ts`. Real devices plug in through `src/sim/live.ts` (see below).
- **Valves.** Valve control is simulated. A real valve needs a local controller that enforces its own limits and fails safe. The web app never commands hardware.
- **Email/SMS.** These need a provider (e.g. Twilio, SendGrid) on a backend.
- **Rebates.** These need a programme sponsor, legal review and utility meter data for verified savings.
- **Map tiles.** Tiles come from OpenStreetMap and need internet access. Markers and the list view still work if tiles fail.

## Connecting the Arduino (Tatil prototype)

The browser **reads** a JSON document from an HTTPS URL every few seconds. Any board can feed it:

```
[Ultrasonic sensor] → [Arduino / ESP32] --WiFi--> [cloud JSON endpoint] <--poll-- [IFRS web app]
```

Endpoint options (pick one): a Supabase table exposed via REST, a Google Apps Script web app, a free key-value store, or ThingSpeak behind a tiny proxy. Boards without Wi-Fi (classic Uno/Nano) can send over USB serial to a laptop script that forwards the JSON.

### Payload contract

```json
{
  "device_id": "dev-t-tatil-lvl",
  "ts": "2026-11-02T14:05:00Z",
  "distance_cm": 38.5,
  "tank_height_cm": 120,
  "battery_v": 4.1,
  "seq": 1043
}
```

| Field | Required | Meaning |
|---|---|---|
| `device_id` | yes | Must match a registered device (`dev-t-tatil-lvl` for the tank, `dev-d-tat` for the drain) |
| `level_pct` *or* `volume_l` *or* `distance_cm` + `tank_height_cm` | tank devices | Level measurement. Distance is from the sensor down to the water surface |
| `drain_level_cm` | drain devices | Water depth in the drain |
| `ts` | no | ISO-8601 or epoch ms. Defaults to time received; future times are rejected |
| `seq` | recommended | Increasing counter. Duplicates and replays are ignored |
| `leak` | no | `true` raises a leak alert |
| `battery_v` | no | Shown as battery % |

Validation: unknown or disabled devices, negative volumes and out-of-range drain levels are rejected. Readings above capacity are flagged as overflow/sensor inconsistency. If the feed stops, the asset goes **stale → offline** and automatic release stops.

To test without hardware, open **Tatil Prototype → Try a sensor message**. To go live, open **Tatil Prototype → Live data source**, paste the HTTPS URL and switch to *Live feed*.

### Production sensor API (for a future backend)

```
POST /api/v1/readings
Authorization: Device <per-device secret>    # or HMAC-SHA256 signature header
Content-Type: application/json
<payload above>
→ 202 Accepted | 400 invalid | 401 bad key | 409 replay (seq) | 429 rate limited

POST /api/v1/valves/{id}/commands            # staff only, audited
{ "action": "open" | "close", "reason": "...", "requested_by": "<user id>" }
→ the controller acknowledges; it may refuse if its local interlocks fail
```

## Release policy (demonstration only)

`src/domain/releasePolicy.ts`. The valve opens only when **every** condition holds:

1. Emergency stop is not engaged.
2. The tank reading is fresh and valid, and the sensor is online.
3. The valve reports no fault.
4. The downstream drain reading is fresh.
5. The drain is below the configured suspend level.
6. The drain is not rising faster than the limit.
7. The tank holds more than the minimum retained volume (plus a small margin).
8. Auto mode is enabled and the time is inside the operating window.
9. The tank has reached the high trigger. Once open, it keeps releasing until it nears the minimum retained volume.

Manual overrides still pass interlocks 1–7, and every action is logged. **A high drain never triggers release.** It suspends it.

## Tests

`npm test` runs 37 unit tests covering the tank calculations, freshness, the release policy (min retained, high drain, fast rise, stale data, faults, e-stop, windows), drain blockage detection, leak detection (including no false alarms from normal use), permissions, idempotent rewards, redemption, rebate workflow/eligibility/estimates, and the live payload adapter.

Manual checklist (all verified in a browser at 375 px and 1280 px):

- [ ] Resident opens a tank and sees volume, capacity, % and last update
- [ ] Simulation slider updates the graphic, alerts and valve decision
- [ ] Bad (120%) reading is flagged; negative reading is rejected
- [ ] Wrightson Rd Tank 1 stays closed because its drain is high; a manual open is blocked
- [ ] Demo Controls → Stale sensor shows the drain as unavailable
- [ ] Leak alert goes acknowledge → inspect → confirm → resolve
- [ ] A resident report, once verified by Devon, gives the reporter 25 points exactly once
- [ ] Cleanup verification awards points once
- [ ] Redemption reduces the balance and appears in history
- [ ] Admin approves a rebate within the funding cap; an applicant can't approve their own
- [ ] A resident can't open another resident's tank
